# Vagus：从人物微动到 Shopify 式画作空间

2026-10-27。此文是制作方案，尚未接入新的三维模型或 WebGL 渲染。本轮完成的动作是二维局部网格试作，不能称为骨骼动画或真实三维。

## 可核实的制作方法

Shopify Editions Winter 2026 官网：https://www.shopify.com/editions/winter2026 。本轮读取了官网页面内容；Chrome 浏览器访问被拒，未连续观察实际滚动或录制动效。技术依据另来自 Shopify 工程负责人 Arnaud Tanielian 于 2025-12-17 发布的第一人称制作拆解，其 Thread Reader 镜像：https://threadreaderapp.com/scrolly/2001335712982147307 。该资料说明使用 Three.js / React Three Fiber；部分画作以深度图驱动细分平面，另一些用模型、绘画贴图、Blender 绑定动画及 glTF；Theatre.js 用于调整时间线，并按设备降级。以上是制作人员说明，不是对我们当前网页的测量。

## 我的判断：差距在哪里

现站有画作、局部动作和滚动镜头，但主体仍在同一张平面图上，画框不能真正遮挡伸出的手，手和道具也没有空间接触阴影。微小变形可以做姿态，却无法补出背面、改变视角或创造真实厚度。继续加大整体缩放会放大这一差距。立体感应按以下顺序建立：先前后遮挡，再道具厚度与落影，再人物小动作，最后才加镜头。画风统一靠绘画贴图与同向光照，不能把光滑塑料模型直接贴在油画上。

## 首个三维试点：关于页的递名片

优先选择关于页，因为画框、前伸手臂与卡片能清楚表达前后关系，制作复杂度低于整个人物雕塑。先锁定当前人物角度和构图。观众看到的顺序应是：墙面在后 → 人物半身 → 手臂伸出 → 名片靠前；下沿画框遮住身体底部，卡片在手指之间。画框与名片可用 Blender 手工建模，不需要 Tripo 付费生成。人物先保持高质量绘画分层。这个版本属于 2.5D 与真实道具混合，完整人物模型另作后续。

| 阶段 | 具体交付 | 通过条件 |
| --- | --- | --- |
| 1. 固定画面 | 当前原画截图基准、文字安全区、画框和卡片角点、静止相机 | 正视构图与原稿重合，人物不换脸、不改服装 |
| 2. 拆资产 | 补全的空墙和画框内背景、人物真实透明层、手臂层、名片前后遮挡蒙版 | 抠出主体后没有重复手指；小幅移动不露空洞 |
| 3. 灰模 | 简单画框厚度、卡片薄片、手部接触位置、同一相机 | 不上材质就能看清前后；名片夹持正确、没有穿插 |
| 4. 绘画材质 | 原画投影纹理、粗糙表面、卡片接触阴影、画框内壁阴影 | 颜色与主光方向吻合，没有塑料亮面或悬浮贴纸感 |
| 5. 动作 | 手臂递出约 0.8 秒、停 0.8 秒、回收约 1.2 秒，其余静止 | 道具与手同步，画框不变形，文字链接全程可读 |
| 6. 微镜头 | 从零位开始，仅极小范围的视差与滚动推进 | 四角不露底，侧面不拉花；失败退回固定相机 |
| 7. 上站 | 海报立即显示，近屏加载三维、离屏暂停、静态回退 | 实机播放与截图验收后才替换当前版本 |

相机先用与原画对齐的正交投影，避免再凭感觉旋转手机或改变人物透视。是否换透视相机由灰模叠图判断。人物、手臂、道具不各自凭屏幕百分比定位，统一使用相机与世界坐标；手指接触点作为约束。运动所露出的区域必须有补全素材，深度图不会自动创造这些内容。

## 其余页面的深度分配

| 页面 | 该立体化的对象 | 画面应保持稳定的部分 |
| --- | --- | --- |
| 首页 | 桌面、冰美式杯体、电脑厚度与桌面阴影；人物分层轻微呼吸 | Vagus、右侧横排理念、透明游戏对话选择、蒙娜丽莎脸 |
| 思想者 | 书本体积、固定手机壳厚度、手指关节与接触位置 | 手机背面朝观众且不旋转；滑 5 秒停 2 秒，无屏幕展示 |
| START | 手与票券处于同一前景组，票券有真实纸厚和微弯 | 原舞会透视、人物脸、右侧项目阅读区 |
| Hug | 水面反光和近远雾，最多浅深度 | 不强加人物或高对比粒子，不扰动正文 |
| 运营 | 红封面厚度、手指夹持、桌沿前景遮挡 | 编辑衣着完整，封面保持直边，不把桌子一起扭动 |
| 播客 | 头部、耳机与背景的轻微分层 | 不扭曲脸，耳机跟随头部，不自动播放声音 |
| 文学节 | 对讲机与手的小幅动作、后台灯光层次 | 舞台结构与文字稳定，不虚构说话或音频 |
| 视觉创作 | 两只手分前后，画笔有厚度与接触阴影 | 中央作品入口清楚，不堆漂浮几何体 |

## 工具选择与范围

制作：Blender；运行：原生 Three.js + glTF；纹理沿用现有油画美术。软件可以免费使用，建模、拆图和绑定仍需要制作时间，不等于一键免费获得 Shopify 成品。现站是原生 HTML/JS，暂不为 R3F 重写成 React。R3F 的可复用组件与时间线组织值得借鉴，但它要求匹配 React 主版本，且不会解决不正确的模型和素材。原生 Three.js 可逐幕增强，保留现有正文、导航和链接。资料：https://github.com/pmndrs/react-three-fiber https://threejs.org/docs/ 。

运行只保留一个渲染器，当前或临近场景加载，离开视口停止。先做静态原画回退，再做画质分级；不为九幕同时开启九个全屏画布。纹理压缩、像素比上限与模型预算由实际设备测量决定。初始目标是桌面稳定 60fps、较弱设备稳定 30fps，测不到不能写已达标；性能不足依次关后处理、降像素比、降纹理，最后返回静态图。减少动态优先于手动开关。

## 明确不采用的做法

不继续把整幅画缩放叫作三维；不在油画后面加陌生自然照片；不为每幕放相同粉蓝配色；不把 UI 烘进贴图；不让手机或卡片与手分别播放独立动画；不用陌生裸露人物替换已经定下的角色；不在模型未经构图确认前开放大幅鼠标旋转。
